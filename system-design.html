How portfolio pages are delivered

Pages, styles, images, and downloads are served as static files. Navigation, filters, and form validation run in the browser. External demos and source repositories remain separate destinations.

Design decision

The public pages are static, while contact messages use a separate POST-only server function connected to my existing private enquiry inbox.

Contact delivery

The form sends a validated message to /api/contact. The function forwards enquiry fields to the existing inbox and confirms success only after acceptance. It cannot read or administer inbox messages.

The adjacent diagram covers page delivery. Contact messages follow the separate enquiry path described here.

From observation to local history

A field report passes through validation before the storage wrapper saves it to IndexedDB. The interface then reads the same local store for history, details, and exports.

Design decision

Local persistence is not remote synchronization. Reports and photos stay in the same browser.

A real project data model

The reports store uses id as its key. Each object keeps its station identifier, observation type, optional level and note, timestamp, optional location, and optional photo Blob.

Design decision

This is an IndexedDB object model, not a relational ERD. Station definitions are code data rather than a second database table.
